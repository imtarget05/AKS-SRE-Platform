Probe Split Architecture: Liveness vs Readiness

Load-bearing SRE decision: /health/live touches event loop ONLY; /health/ready checks downstream dependency.

GET /health/live HTTP 200 OK

Answers "is the Node.js event loop alive?". It NEVER touches the database or upstream dependencies. If dependencies slow down or fail, this probe remains healthy, preventing catastrophic Kubernetes restart loops!

Answers "should this pod receive traffic?". It DOES depend on downstream readiness. When a dependency fails, the Service drops the pod endpoint with 0 RESTARTS.
