## Out of core scope

[ADR-019](../adr/019-platform-scope-and-workload-isolation.md) makes `apps/agent-hub` optional and non-blocking. Its [README](../../apps/agent-hub/README.md) describes local HITL tests, a local image, single-replica SQLite PVC, shared signing key and missing production identity/HA; it explicitly disclaims AKS readiness. Do not count it in core platform completion. Include it in a separately named extension denominator only if product scope is changed in ADR/PRD.

## Source conflicts to repair during implementation

- `README.md` still says no persistent cluster or live Azure CI proof and calls this repository a blueprint, while 2026-10-25 evidence records a running AKS platform. Use dated live evidence and new read-only probes, then update the narrative.
- `tasks/current.md` opens with an obsolete all-gates-100% headline and later contradicts itself; `terraform/README.md` also says no successful apply despite Phase 7A and 2026-10-25 evidence. Do not use those headlines for acceptance.
- `platform/observability/README.md` instructs applying files under that directory that are no longer there; current ServiceMonitor/PrometheusRule manifests live under `deploy/base/observability/`. The installation runbook must be corrected before an AKS monitoring rollout.

## Phase 0 exit checklist

Assign a named owner and reviewer to every row, confirm requirement priority and release scope, bind each to a current commit and image digest, run relevant tests, and attach immutable cloud evidence. Randomly check 10% of rows with another reviewer. Until then, no official percentage is calculated from this baseline.
